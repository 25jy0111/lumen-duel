# 自宅PCのCodexへ貼り付けるプロンプト

以下のコードブロック全体を、新しいPCのCodexへ貼り付けてください。まだcloneしていなくても、作業可能なフォルダでCodexを開いて渡せます。すでにclone済みなら、そのプロジェクトフォルダで新しいCodexセッションを始めると確実です。

```text
学校PCで開発した卒業制作のWebカードゲームを、このPCのCodexに引き継ぎたいです。
私は基本的に実装を行わないので、環境確認・取得・起動・テストまで進めてください。

プロジェクト名：LUMEN DUEL / ルーメンデュエル
GitHub：https://github.com/25jy0111/lumen-duel
clone URL：https://github.com/25jy0111/lumen-duel.git
主ブランチ：main
公開ゲーム：https://25jy0111.github.io/lumen-duel/

これはGod Fieldの基本システムを参考にしたオリジナルゲームです。
TypeScript / React / Vite / Vitest、npm、Gitを使用しています。
第一段階の「人間対CPUで開始から決着・再戦まで遊べるゲーム」は完成・公開済みです。
今は引き継ぎと動作確認が目的で、作り直しやオンライン対戦の新規実装は依頼していません。

次の順序で実際に作業してください。
1. 現在の作業フォルダとGitの状態、OS、Git・Node.js・npmの有無を確認する。
   既存ファイルを上書きせず、未取得なら新しい専用フォルダへこのリポジトリをcloneする。
   取得済みならremoteと変更を確認し、未コミット変更がなくmainで安全に更新できる場合だけ
   fetch / pull --ff-onlyする。既存作業をresetやforce pushで消さない。
2. AGENTS.md、docs/handoff.md、README.md、docs/rules.md、docs/design.mdを読み、
   コードと設定を確認してから作業する。会話履歴がなくてもこの資料を基に引き継ぐ。
3. Node.jsはプロジェクト指定の22.12以上（24系推奨）を使う。
   足りない環境は権限の範囲で整え、npm ci、npm test、npm run buildを実行する。
   学校PC固有の絶対パス・認証情報・スキル・プラグインに依存しない。
4. ローカルで起動してアクセス先を示す。可能ならブラウザで攻撃・防御・CPU行動・勝敗・再戦を確認する。
   ブラウザテストのBROWSER_PATHとGAME_URLは、このPCのOS・ブラウザ・起動先に合わせる。
   起動や検証に問題があれば原因を調べ、引き継ぎに必要な範囲で修正し、変更と検証結果を記録する。
5. 認証情報をファイルや会話に出さない。公開リポジトリのcloneには認証不要だが、
   将来のpushはこのPCでGitHubの書き込み認証を行う。学校PCのトークンをコピーしない。
6. 最後に、取得先・現在の状態・実行したテスト・起動方法・制限・次にできることを日本語で簡潔に報告する。
   今回は新機能の追加やmainへのpushを目的にせず、まずこのPCで開発を再開できる状態にする。

守る方針：
・ゲームエンジン、カードデータ、CPU、React画面を分離する。
・人間とCPUは同じゲームエンジンを使う。
・自由な手札交換は導入しない。「祈る」「捨てる」はdocs/rules.mdに従う。
・God Fieldの正式仕様と、このゲームの暫定仕様を混同しない。
・小さく完成させながら拡張し、現段階で不要な汎用基盤を作らない。
・mainへのpushは公開ゲームの自動更新につながるので、反映する依頼の範囲を把握する。
・細かな実装方法の確認は不要。合理的に判断して作業し、設計案だけで終了しない。
・本人のログイン、権限不足、重大な方針判断が必要な場合だけ質問する。
  その場合も、先にできることをすべて進め、必要な操作と質問をまとめて伝える。
```

## 引き継ぎ後に機能開発を頼む場合

環境確認が終わったあと、同じ会話に次の形で目的を追加してください。

```text
次は「ここに作りたい機能や直したい問題を書く」を実装してください。
現在のコードとdocs/rules.md・docs/design.mdを確認し、必要な変更・テスト・文書更新まで行ってください。
細部は合理的に判断し、重大なルール変更や私の操作が必要な事項だけ、まとめて確認してください。
最後に変更点、検証結果、操作方法、制限を報告してください。
```

公開版にも反映させたい場合は「検証後、GitHubへのcommit/pushと公開版への反映確認までお願いします」を追記します。`main` へのpushで自動公開されるため、手元だけで試す依頼とは区別してください。
